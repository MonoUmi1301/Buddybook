## Post-roadmap — OAuth (Google + LINE), re-prioritized by user after Phase 9
Originally deprioritized in the Phase 1 kickoff ("ยังไม่ทำตอนนี้"), reactivated after the user obtained real Google Cloud Console and LINE Developers credentials mid-session.
- [x] **Backend, provider-agnostic**: `lib/oauthProfile.ts` defines a shared `OAuthProfile` shape; `lib/googleOAuth.ts` and `lib/lineOAuth.ts` each implement `buildXAuthUrl(state)` + `exchangeXCode(code): Promise<OAuthProfile>` against it, gated by `isXOAuthConfigured()` (same pattern as Cloudinary/SlipOK — missing credentials degrade to a clear 400, not a boot crash). `auth.service.ts` has one `loginOrRegisterWithOAuth(profile)` used by both providers: matches on `(oauth_provider, oauth_id)` first, falls back to linking an existing password account by email (not duplicating it), generates a collision-safe username from the email prefix otherwise.
- [x] **CSRF protection without a session store**: the whole app is stateless JWT (no server-side sessions), so `state` is an HMAC(JWT_SECRET) of a random nonce — verified by recomputing the signature on callback, not by comparing against anything stored server-side.
- [x] **LINE-specific**: LINE's OpenID `id_token` is verified via LINE's own `POST /oauth2/v2.1/verify` (returns already-validated claims) rather than hand-rolling JWKS verification. LINE only returns `email` if the channel has that permission granted in LINE Developers Console *and* the user consents — when absent, falls back to a `line_<sub>@line.buddybook.local` placeholder so the `email` unique constraint is never violated.
- [x] **Routing**: Next.js gets two new generic (provider-parameterized) route handlers — `GET /api/v1/auth/oauth/[provider]` (asks Express for the real provider auth URL, 302s the browser there) and `GET /api/v1/auth/oauth/[provider]/callback` (receives the provider's redirect with `?code&state`, POSTs to Express, sets the same httpOnly cookies as normal login, redirects home). Express's existing `GET/POST /auth/oauth/:provider(/callback)` stub routes (already scaffolded since Phase 1) were filled in for real instead of adding new paths.
- [x] Frontend: the "เข้าสู่ระบบด้วย Google" / "เข้าสู่ระบบด้วย Line" buttons on `AuthForm.tsx` (login and register both) now actually navigate instead of being inert.
- [x] Credentials stored in `apps/api/.env` (gitignored, confirmed) — `GOOGLE_CLIENT_ID/SECRET`, `LINE_CLIENT_ID/SECRET`, `APP_URL` (used to build the exact `redirect_uri` sent to each provider — must stay byte-identical to what's registered in each console; update this one value on deploy, no code changes needed).
- [x] Verified as far as is safe to automate: hit `GET /auth/oauth/google` and `GET /auth/oauth/line` directly — both return real, correctly-formed provider auth URLs with the right `client_id`/`redirect_uri`/`scope`/`state`.
