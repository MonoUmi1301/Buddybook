## KPI-1 / KPI-2 — ระบบแนะนำ (offline evaluation บน mock data)

```bash
cd apps/api
npx tsx scripts/eval-recs.ts --seed 42 --csv ../../docs/results/eval-recs-seed42.csv
```

- ใช้โค้ดจัดอันดับตัวจริง (`src/modules/recommendations/ranking.ts`) ส่วนการดึง candidate จำลอง query ของ
  `recommendations.service.ts` ในหน่วยความจำ — ไม่ต้องมีฐานข้อมูล ได้ผลเดิมทุกครั้งเมื่อ seed เท่าเดิม
- โลกจำลอง: นิยาย 600 เรื่อง, ผู้ใช้ 300 คน, อ่านคนละ 20 เรื่อง โดย**การมองเห็นเอียงไปทางเรื่องดังแบบ power-law ที่ไม่ขึ้นกับคุณภาพ**
  (จำลอง popularity bias) ผู้ใช้เลือกความสนใจตอน onboarding ถูกต้อง 70%
- **Ground truth** = เรื่องที่ยังไม่อ่าน ตรงแนวที่ผู้ใช้ชอบจริง และคุณภาพ ≥ 0.5
- **Long-tail** = นิยายที่ยอดวิวไม่อยู่ใน 20% บนสุด (นิยามตาม Abdollahpouri et al.)

| อัลกอริทึม | Precision@10 | สัดส่วน long-tail | Catalog coverage |
|---|---|---|---|
| ยอดนิยม (baseline) | 5.9% | 0.0% | 3.3% |
| v1 เดิม (ก่อนแก้) | 43.7% | 75.7% | 12.5% |
| v2 ไม่ re-rank (λ = 0) | 85.9% | 21.0% | 17.8% |
| **v2 + re-rank (λ = 0.3)** | **85.8%** | **40.7%** | **28.5%** |

อ่านผล: re-ranking เพิ่มสัดส่วน long-tail เกือบ 2 เท่าโดย precision ลดลงแค่ 0.1 จุด และกระจายการแนะนำไปทั่วคลังมากขึ้น
(coverage 17.8% → 28.5%) v1 มี long-tail สูงแต่ precision ต่ำ เพราะส่วน "underrated" เดิมจัดอันดับด้วยความมั่นใจของโมเดล
แทนขั้วความรู้สึก (รีวิวติแรงถูกนับเป็นชอบ — แก้แล้วใน gap 2.1)

**ข้อจำกัด:** เป็นข้อมูลจำลอง (ตามที่ Proposal ระบุ "Mock Data") ช่วง UAT มีผู้ใช้ 30 คน ข้อมูลเบาบางเกินกว่าจะวัด
precision ได้มีความหมาย จึงใช้ UAT วัดความพึงพอใจอย่างเดียว

## Sentiment model — วัดบนชุดทดสอบแยก

```bash
cd apps/nlp-worker
python eval/evaluate.py --model <โฟลเดอร์โมเดล> --train-data <novel_dataset.csv> --out ../../docs/results/sentiment-eval.md
```

ผลเต็มอยู่ที่ `docs/results/sentiment-eval.md` (วัดเมื่อ 14 ต.ค. 2569)

**ทำไมไม่ใช้ 99.33% จาก notebook:** `novel_dataset.csv` มี 1,608 แถว แต่เป็นประโยคที่ต่างกันจริงแค่ 164 ประโยค
(แถวที่เหลือคือประโยคเดิมที่ต่อท้ายด้วยเลข เช่น `(77)`) เมื่อแบ่ง train/test แบบสุ่ม ประโยคในชุดทดสอบราว 93%
จึงอยู่ในชุดเทรนแบบคำต่อคำ ตัวเลข 99.33% จึงวัดการจำข้อมูล ไม่ได้วัดความสามารถกับข้อความใหม่

**ชุดทดสอบใหม่** (`apps/nlp-worker/eval/test_set.csv`): 180 ประโยคที่เขียนใหม่ (pos/neg/neutral กลุ่มละ 60)
และตรวจด้วย script แล้วว่าไม่ซ้ำหรือเกือบซ้ำกับ `novel_dataset.csv` label ตามความรู้สึกต่อตัวนิยาย
ประชดนับเป็น neg (ตรงกับตอนเทรน) และด่าตัวละครเพราะอินนับเป็น pos

| โมเดล | Accuracy | Macro-F1 | ไม่นับกลุ่มด่าตัวละครเพราะอิน |
|---|---:|---:|---:|
| v1 (`my_final_sentiment_model`) | 68.9% | 0.688 | 121/155 = 78.1% |
| v2 (ตัวที่ worker ใช้อยู่) | **77.8%** | **0.773** | 140/155 = **90.3%** |
| v3 | 73.9% | 0.733 | 133/155 = 85.8% |

| ประเภทข้อความ | v1 | v2 | v3 |
|---|---:|---:|---:|
| ชมงาน | 31/35 | 31/35 | 27/35 |
| ติงาน/ด่างาน | 33/35 | 34/35 | 34/35 |
| ชมประชด | 6/25 | 21/25 | 22/25 |
| ด่าตัวละครเพราะอิน | 3/25 | 0/25 | 0/25 |
| กลาง (คำถาม/เช็กชื่อ/เฉยๆ) | 51/60 | 54/60 | 50/60 |

**สรุป**

- โมเดลแยกชมกับด่างานได้ดี และ v2/v3 จับประชดได้ 84–88% หลังเพิ่มตัวอย่างประชดในชุดเทรน
- **ข้อจำกัดหลัก:** โมเดลทายข้อความที่ด่าตัวละครเพราะอินในเรื่อง (เช่น "อีนางร้ายน่าตบมาก ไรท์เขียนเก่ง") เป็น neg เกือบทั้งหมด
  เพราะชุดเทรนไม่มีตัวอย่างแบบนี้ ระบบแนะนำจึงอาจให้คะแนนนิยายดราม่าที่คนอ่านอินมาก ๆ ต่ำกว่าที่ควร
- ชุดทดสอบเขียนและ label โดยทีมพัฒนา ยังไม่ใช่คอมเมนต์จริง และ 180 ประโยคมีช่วงความเชื่อมั่นของ accuracy ราว ±7 จุด
  ถ้ามีคอมเมนต์จริงช่วง UAT ควรนำมา label แล้วรันซ้ำด้วย script เดียวกัน

### ปรับปรุงหลังวัดผล (ต.ค. 2569)

ทำต่อจากข้อจำกัดข้างบนเป็น 3 ขั้น วัดทุกขั้นด้วยชุดทดสอบเดิม (`test_set.csv`) และจูนด้วยชุดแยก
`eval/dev_set.csv` (60 ประโยค มีคอลัมน์ชื่อตัวละคร) เพื่อไม่ให้จูนกับชุดที่ใช้รายงานผล

**1. แยกเป้าหมายความรู้สึก (ตัวละคร vs ตัวงาน)** — `apps/nlp-worker/src/target.py`
กฎหลังโมเดล: ทาย neg + ไม่มีคำวิจารณ์งาน (คำผิด พล็อต ดอง ไม่คุ้ม ฯลฯ) + พูดถึงตัวละคร (คำเรียกบทบาท หรือชื่อตัวละครของ
นิยายเรื่องนั้นที่ API ส่งมากับคิว) หรือมีคำที่บอกว่าอินจัด → นับเป็น pos ขั้ว +0.5 ไม่เพิ่มคลาส ไม่แตะ schema

| v2 บน test_set | Accuracy | Macro-F1 | ด่าตัวละครเพราะอิน | ติงาน | ชมประชด |
|---|---:|---:|---:|---:|---:|
| โมเดลอย่างเดียว | 77.8% | 0.773 | 0/25 | 34/35 | 21/25 |
| + กฎ target | **89.4%** | **0.895** | **23/25** | 33/35 | 19/25 |

ข้อแลก: 3 ประโยคที่พูดถึงตัวละครแต่จริง ๆ ติงานเขียน (เช่น "ตัวละครเยอะเกินจนจำไม่ได้…") ถูกพลิกเป็น pos ผิด

**2. Temperature scaling** — `apps/nlp-worker/eval/calibrate.py`, ตั้งด้วย `SENTIMENT_TEMPERATURE`
โมเดลตอบความมั่นใจ ~0.99 แม้ทายผิด ปรับ `softmax(log p / T)` (label ไม่เปลี่ยน) เลือก T จาก log-loss บน dev_set
เฉพาะประโยคที่กฎข้อ 1 ไม่ได้พลิก ได้ T = 1.5 — บน test_set: log-loss 0.499 → 0.427, ECE 0.084 → 0.067,
Brier 0.211 → 0.213 (เท่าเดิม) ได้ผลพอประมาณ เพราะค่าที่ติด −1 ตอนทายผิดส่วนใหญ่มาจากกลุ่มด่าตัวละครที่ข้อ 1 แก้แล้ว

**3. เทรนต่อเป็น v4** — `apps/nlp-worker/train/` (สร้างชุดข้อมูล → เทรนบน Colab GPU → วัดผลก่อนใช้จริง)

ตัดประโยคซ้ำ (1,446 แถว) และตัดทุกประโยคที่ซ้ำ/เกือบซ้ำกับ test_set หรือ dev_set (trigram ≥ 0.6 เกณฑ์เดียวกับ evaluate.py)

อ้างอิง Wisesight: Suriyawongkul et al. (2019) doi:10.5281/zenodo.3457447

**วัดบนข้อมูลจริงด้วย:** ชุดทดสอบทางการของ Wisesight (2,674 ข้อความ, `eval/wisesight_test.py`) ไม่อยู่ในชุดเทรน

| โมเดล | Wisesight test Accuracy | Macro-F1 | test_set (180) |
|---|---:|---:|---:|
| v2 | 70.5% | 0.647 | 77.8% (+กฎ target 89.4%) |
| v4 รอบแรก — **ทิ้ง** | 62.6% | 0.614 | 87.8% |
| **v4 (ใช้อยู่)** | **74.3%** | **0.715** | **93.9%** (+กฎ target 92.2%) |

v4 รอบแรกเทรนบนข้อมูลที่ label ของ Wisesight เลื่อนแถว (~60% ผิด — บั๊ก `splitlines()` ใน build_dataset.py แก้แล้ว
พร้อมเทสต์) จึงแย่ลงบนข้อมูลจริงแม้ test_set ที่ทีมเขียนจะดีขึ้น — v4 รอบใหม่ใช้ Wisesight ทั้งชุดที่ label ถูกต้อง
เปลี่ยนไปใช้ก็ต่อเมื่อดีกว่า v2 **ทั้ง** Wisesight test และ test_set (เทียบกับ v2+กฎ target)

**ผล v4 (เทรนบน Colab T4, Wisesight ทั้งชุด 15,506 แถว, คอมเมนต์นิยายที่แต่งถ่วงน้ำหนัก ×8, 3 epoch):**
ดีกว่า v2 ทั้งสองชุด จึงเปลี่ยนมาใช้ (`apps/nlp-worker/model/`; สำรอง v2/v4 ไว้ที่ buddybook_real)

- v4 เรียนเคส "ด่าตัวละครเพราะอิน" ได้เองจากข้อมูล เปิดกฎ target ซ้อนแล้วแย่ลง (93.9% → 92.2%) จึงปิดกฎ
  (`SENTIMENT_TARGET_RULE=0`) — กฎยังอยู่ในโค้ด เปิดได้ถ้าย้อนไปใช้ v2
- calibrate ได้ T = 1.0 (ECE บน test_set 0.019 เทียบ v2 0.084) จึงไม่ต้อง temperature scaling (`SENTIMENT_TEMPERATURE=1.0`)

**2. ป้ายเป้าหมาย (ใช้กับ v4, ได้หลายป้าย)** — `target.classify_targets` ติดป้าย "เพิ่ม" ว่าความรู้สึกพุ่งไปที่
ตัวละคร / การอินกับเหตุการณ์ / ตัวงานเขียน โดยไม่แตะ label และ polarity ของโมเดล (ความแม่น v4 ยังเป็น 93.9%)
ข้อความเดียวมีได้หลายป้าย เช่น "นางเอกฉลาด แต่คำซ้ำเยอะ" = ตัวละคร + งานเขียน (รุ่นแรกเก็บได้ป้ายเดียว ป้ายงานเขียนจึงหายไป)
เก็บใน `comments/reviews.sentiment_targets` (array) หน้าสถิตินักเขียนใช้**เฉพาะฝั่งบวก**: สัดส่วนข้อความเชิงบวกที่ผู้อ่านอินกับเรื่อง
และตัวละครที่ถูกพูดถึงบ่อย — ป้าย "งานเขียน" และตัวเลขเชิงลบดูได้ที่หลังบ้าน `/admin/sentiment` เท่านั้น

คำติงานที่เพิ่มสำหรับติดป้าย (`WORK_TAG_EXTRA_WORDS`: คำซ้ำ, ประโยคซ้ำ, ตรวจทาน, เรียบเรียง ฯลฯ) แยกจาก `WORK_CRITICISM_WORDS`
ที่กฎพลิกของ v2 ใช้ เพื่อให้ตัวเลข v2 + กฎ ข้างบนไม่เปลี่ยน

ผลบน test_set (180 ประโยค, ไม่ได้ใช้ปรับคำ) — `python -m unittest tests/test_classify_target.py`
นับ "มีป้ายนั้นอยู่ด้วย" (ข้อความที่มีหลายป้ายนับในทุกคอลัมน์ที่ตรง)

| ประเภทในชุดทดสอบ | ตัวละคร/อิน | งานเขียน | ไม่ระบุ | มีหลายป้าย |
|---|---|---|---|---|
| อินกับเรื่อง (25) | **24 (96%)** | 2 | 1 | 13 |
| ชม (35) | 5 | 8 | 22 | 0 |
| ติ (35) + ประชด (25) | 5 | **31 (52%)** (ป้ายเดียว: 28) | 26 | 2 |
| ถาม / ทักทาย / เฉย ๆ (60) | 4 | 0 | 56 | 0 |

ข้อจำกัด: เป็นกฎคำสำคัญ ฝั่ง "ติงาน" จับได้ราวครึ่งเดียว จึงใช้ดูแนวโน้มในหลังบ้าน ไม่แสดงให้นักเขียน

**3. ผสมดาวเข้ากับขั้วของรีวิว** — โมเดลอ่านรีวิวที่ทั้งชมทั้งติ (เช่น "โดยรวมดี นางเอกฉลาด แต่คำซ้ำเยอะ") เป็นบวกเกือบเต็ม (+0.95)
แต่ผู้อ่านให้ 4 ดาว ระบบจึงเก็บ 2 ค่าแยกกัน:

- `reviews.sentiment_polarity` = **ค่าดิบ** จากข้อความ (P(pos) − P(neg) ของโมเดล) ไม่ถูกแก้
- `reviews.blended_polarity` = **หลังผสมดาว** = 0.5 × ค่าดิบ + 0.5 × (ดาว − 3) / 2 ; ไม่มีดาว = ค่าดิบ (`blendReviewPolarity` ใน `lib/sentiment.ts`)

ระบบแนะนำ (READ edge ใน Neo4j และค่าเฉลี่ยรายเรื่อง) ใช้ `blended_polarity` ส่วนคอมเมนต์ยังใช้ค่าดิบเพราะไม่มีดาว

| ตัวอย่าง | ค่าดิบ | ดาว → ขั้วดาว | หลังผสมดาว |
|---|---|---|---|
| ชมล้วน | +0.95 | 5 → +1.0 | +0.975 |
| ชมแต่ติ (เคสจริงที่ทดสอบ) | +0.95 | 4 → +0.5 | **+0.725** |
| ข้อความบวกแต่ให้ 3 ดาว | +0.90 | 3 → 0 | +0.45 |
| ด่าตัวร้ายเพราะอิน แต่ให้ 5 ดาว | −0.60 | 5 → +1.0 | +0.20 |
| ติแรง | −0.97 | 1 → −1.0 | −0.985 |

ตารางจากข้อมูลจริงในฐานข้อมูล (แยกตามดาว: จำนวน pos/neutral/neg, ค่าดิบเฉลี่ย vs หลังผสมดาว, ป้ายต่อแหล่ง)
พิมพ์ได้ด้วย `cd apps/api && npm run report:sentiment` และดูได้ที่หน้า `/admin/sentiment`
(ข้อมูลจาก `seed:scale` เป็นข้อมูลจำลองที่ผูกอารมณ์กับดาวไว้แล้ว ตารางจะมีความหมายเมื่อเป็นรีวิวจริงที่ worker วิเคราะห์)
- ข้อควรระวังเดิม: test_set/dev_set และคอมเมนต์นิยายในชุดเทรนเขียนโดยทีมเดียวกัน คะแนน 93.9% จึงอาจสูงกว่าคอมเมนต์จริง
  ตัวเลขที่อิงข้อมูลจริงคือ Wisesight test (74.3%) — ควรเก็บคอมเมนต์จริงจากผู้ใช้มา label และวัดซ้ำหลังเปิดใช้งาน
(ข้อควรระวัง: test_set และ dev_set เขียนโดยทีมพัฒนา ไม่ใช่คอมเมนต์จริงของผู้ใช้)
