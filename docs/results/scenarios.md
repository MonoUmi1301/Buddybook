# Scenario-based testing ตาม User Flow

ทดสอบตาม `BuddyBook Userflow.pdf` ผ่านเว็บจริง (Docker profile `prod`: `next build` + `next start`, API, Postgres, Neo4j)
บนเครื่องพัฒนา เมื่อ 14 ต.ค. 2569 ใช้บัญชีทดสอบจาก `npx tsx prisma/seed-e2e.ts --rich`
(นักเขียน `e2e_writer`, ผู้อ่าน `e2e_reader1–12`, แอดมิน `e2e_admin` รหัสผ่านอยู่ในไฟล์ seed)

ผลรวม 22 สถานการณ์: **ผ่าน 16 · ผ่านแต่มีข้อสังเกต 4 · ไม่ผ่าน 2** และอีก 4 สถานการณ์ต้องทดสอบด้วยมือ

## ผลทดสอบ

| # | สถานการณ์ (User Flow) | ขั้นตอน | ผลที่คาด | ผลจริง | สถานะ |
|---|---|---|---|---|---|
| S1 | Guest mode บางฟีเจอร์ถูกล็อก | ไม่ล็อกอิน เปิดหน้าแรก แล้วเข้า `/write` และ `/library` | หน้าแรกเปิดได้ ส่วนหน้าที่ต้องล็อกอินถูกพาไปหน้าเข้าสู่ระบบ | หน้าแรกแสดงครบ ส่วน `/write` และ `/library` ถูกพาไป `/login` | ✅ ผ่าน |
| S2 | หน้าเข้าสู่ระบบมีทุกช่องทาง | เปิด `/login` | มี LINE, Google, Facebook และอีเมล/รหัสผ่าน | มีครบ ไม่มี Apple (ตัดออกตามที่ตกลง) | ✅ ผ่าน |
| S3 | เข้าสู่ระบบไม่สำเร็จ → แจ้งเตือน → ลองใหม่ | ใส่รหัสผ่านผิด แล้วใส่รหัสที่ถูก | แจ้งเตือน แล้วเข้าได้เมื่อรหัสถูก | ขึ้น "อีเมลหรือรหัสผ่านไม่ถูกต้อง" และเข้าได้เมื่อใส่รหัสที่ถูก | ✅ ผ่าน |
| S4 | Onboarding บังคับ ข้ามไม่ได้ | ผู้ใช้ที่ยังไม่เลือกความสนใจเข้าระบบ ลองเปิด `/search` ตรง ๆ แล้วทำ 3 ขั้น | ถูกพากลับ onboarding เสมอ ปุ่มถัดไปกดไม่ได้จนกว่าจะเลือก | ถูกพาไป `/onboarding` ปุ่มถัดไปถูกปิดจนกว่าจะเลือก ทำครบ 3 ขั้นแล้วบันทึกได้ (201) | ✅ ผ่าน |
| S4b | Onboarding บังคับ เมื่อใช้เบราว์เซอร์ร่วมกัน | ผู้ใช้ A ออกจากระบบ ผู้ใช้ B ที่ยังไม่ทำ onboarding เข้าระบบในเบราว์เซอร์เดียวกัน แล้วเปิด `/search` | ถูกพาไป onboarding | **เข้า `/search` ได้เลย** เพราะ cookie `bb_has_interests=1` ของ A ไม่ถูกลบตอนออกจากระบบ | ❌ ไม่ผ่าน (B1) |
| S5 | หน้าแรกแนะนำนิยายตามความสนใจ | หลัง onboarding เปิดหน้าแรก แล้วเรียก `GET /recommendations` | มีส่วน "เรื่องที่คุณอาจสนใจ" ที่มาจากกราฟ Neo4j | ครั้งแรก**ใช้กราฟไม่ได้** (`graph_available: false`) ทุกเรื่องเป็น "ยอดนิยม" เพราะกราฟว่าง หลังสั่ง resync เองได้เหตุผล interest และ hidden gem และ 7/10 เป็น long-tail | ❌ ไม่ผ่าน (B2) |
| S6 | ค้นหาและกรองแท็ก | ค้นด้วยชื่อเรื่อง, กรอง `genre_ids` (แฟนตาซี), กรองชื่อผู้แต่ง, และรวมคำค้นกับหมวด | ได้เฉพาะเรื่องที่ตรงเงื่อนไข | ตรงทุกกรณี (นับรวมเรื่องที่ตั้งหมวดหลักเป็นแฟนตาซีด้วย) | ✅ ผ่าน |
| S7 | หน้าแสดงเนื้อหานิยาย → อ่านตอน | เปิดหน้านิยาย กด "เริ่มอ่านตอนแรก" | เปิดตอนแรกที่เผยแพร่แล้ว | เปิดตอนที่ 2 เพราะตอนที่ 1 ยังเป็น draft ถูกต้อง | ✅ ผ่าน |
| S8 | ชั้นหนังสือ | กด "เพิ่มเข้าชั้น" | ปุ่มเปลี่ยนสถานะ | เปลี่ยนเป็น "อยู่ในชั้นแล้ว" | ✅ ผ่าน |
| S9 | คอมเมนต์และรีวิว | คอมเมนต์ในตอน และรีวิว 5 ดาว | แสดงทันที คะแนนเฉลี่ยอัปเดต | คอมเมนต์จาก 2 เป็น 3, คะแนนจาก 4.7 (3) เป็น 4.8 (4) | ✅ ผ่าน |
| S10 | Sentiment → Neo4j | รัน NLP worker (v2) กับคอมเมนต์และรีวิวที่เพิ่งส่ง | ได้ label และ `READ.sentiment_score` อัปเดต | รีวิวได้ pos ส่วนคอมเมนต์ "ตัวร้ายเลวมาก แค้นแทนนางเอก" ได้ neg (ข้อจำกัดที่รู้แล้ว) `READ.sentiment_score = 0.20` ตรงกับสูตร 0.6×รีวิว + 0.4×คอมเมนต์ | ⚠️ ผ่านแต่มีข้อสังเกต |
| S11 | ออกจากระบบ | กด "ออกจากระบบ" แล้วเปิด `/library` | กลับเป็น guest | ถูกพาไป `/login` | ✅ ผ่าน (ดู B1 เรื่อง cookie ที่ค้าง) |
| S12 | สร้างนิยายใหม่ | `/write/new` กรอกชื่อและเรื่องย่อ แล้วสร้าง | สร้างได้ และเลือกขั้นต่อไปได้ | สร้างได้ และพาไปหน้าเลือก "ไปเขียนตอนแรก / เครื่องมือ" | ✅ ผ่าน |
| S13 | สร้างเนื้อหานิยาย + autosave | เขียนตอน กดบันทึกร่าง แล้วพิมพ์ต่อโดยไม่กดบันทึก รอ 30 วิ | บันทึกเองอัตโนมัติ | `PATCH /autosave` ได้ 200 ขึ้น "บันทึกแล้ว" ใน DB มีเนื้อหา 92 ตัวอักษรและ 1 เวอร์ชัน | ✅ ผ่าน |
| S14 | หน้าสร้างพล็อต (เครื่องมือนักเขียน) | สร้างตัวละคร 2 ตัว + เส้นความสัมพันธ์, เหตุการณ์ไทม์ไลน์, สถานที่ แล้ว reload | ข้อมูลยังอยู่และแสดงบนแผนผัง | แผนผังตัวละครแสดง 2 node + เส้น "ศัตรู", ไทม์ไลน์อยู่ในแท็บ Environment, สถานที่อยู่บนแผนที่ในแท็บ Base | ✅ ผ่าน |
| S15 | หน้าเครื่องมือและหน้าบัญชีเปิดได้ | เปิด plot, theme, characters, environment, base, print-preview, trash, stats, library, wallet, settings, notifications, support | 200 ทุกหน้า | 200 ทุกหน้า ใช้เวลา 59–293 ms | ✅ ผ่าน |
| S16 | ลบนิยาย → นิยายที่ถูกลบ → กู้คืน | ลบนิยาย แล้วเปิดหน้าสาธารณะและหน้าถังขยะ แล้วกดกู้คืน | ย้ายไปถังขยะ 30 วัน, หน้าสาธารณะหายไป, กู้คืนแล้วข้อมูลครบ | ขึ้น "จะถูกลบถาวรในอีก 30 วัน" หน้าสาธารณะเป็น 404 และกู้คืนแล้วได้ตอนกับตัวละครกลับมาครบ | ✅ ผ่าน |
| S17 | ลบถาวร: ยกเลิก / ยืนยัน | กดลบถาวร → ยกเลิก แล้วลบถาวร → ยืนยัน | ยกเลิกแล้วยังอยู่ ยืนยันแล้วหายถาวร | กล่องเตือน "หากลบจะไม่สามารถกู้คืนได้อีกครั้ง" ยกเลิกแล้วยังอยู่ ยืนยันแล้วลบจาก DB จริง แต่ API ตอบช้าจนได้ 504 หน้าเว็บจึงยังแสดงรายการเดิมจนกว่าจะรีเฟรช | ⚠️ ผ่านแต่มีข้อสังเกต (B4) |
| S18 | แก้ไข Profile | แก้คำแนะนำตัว บันทึก แล้ว reload | ค่าใหม่ยังอยู่ | ยังอยู่ | ✅ ผ่าน |
| S19 | เปลี่ยนธีม | สลับธีมจากเมนูผู้ใช้ | เปลี่ยนทันทีและจำค่าไว้ | สลับมืด/สว่างได้ และจำค่าใน `bb_theme` | ✅ ผ่าน |
| S20 | ซื้อเหรียญ | เปิด `/wallet` | แสดงยอด coin และแพ็กเกจ | แสดงแพ็กเกจ 6 ขนาด (25–825 coin) | ⚠️ ผ่านเฉพาะหน้าจอ ยังไม่ได้ทดสอบจ่ายเงินจริง |
| S21 | ระบบแนะนำหลังทำ onboarding เสร็จ | ทำ onboarding เสร็จแล้วดูหน้าแรกทันที | มีคำแนะนำ | ครั้งแรกส่วนแนะนำว่าง ต้องรีเฟรชหนึ่งครั้งถึงจะขึ้น | ⚠️ ผ่านแต่มีข้อสังเกต (B5) |

### ต้องทดสอบด้วยมือ (ใช้บัญชีหรืออีเมลจริง)

| สถานการณ์ | เหตุผล |
|---|---|
| สมัครสมาชิกด้วยอีเมล + ยืนยัน OTP | ระบบส่ง OTP ผ่าน Resend ไปที่อีเมลจริง |
| เข้าสู่ระบบด้วย Google / Facebook / LINE | ต้องใช้บัญชีจริงของผู้ให้บริการ |
| ลืมรหัสผ่าน | ส่งอีเมลจริง |
| เติมเหรียญจนเงินเข้าบัญชี | ต้องรัน `node scripts/stripe-listen.mjs` แล้วจ่ายด้วยบัตรทดสอบของ Stripe |

## ข้อบกพร่องที่พบ

| รหัส | ระดับ | ปัญหา | ผลกระทบ | แนวทางแก้ |
|---|---|---|---|---|
| B1 | สูง | ออกจากระบบแล้ว cookie `bb_has_interests` ไม่ถูกลบ (`apps/web/src/app/api/v1/auth/logout/route.ts`) middleware จึงคิดว่าผู้ใช้คนถัดไปทำ onboarding แล้ว | ข้าม onboarding ได้เมื่อใช้เบราว์เซอร์ร่วมกัน ซึ่งขัดกับ requirement ที่ว่า onboarding ข้ามไม่ได้ | ลบ cookie ตอน logout และตั้งค่าใหม่ตอน login จาก `has_interests` ของผู้ใช้ที่เพิ่งเข้าระบบ |
| B2 | สูง | job `recommendations-full-resync` ไม่ได้ตั้ง `runOnStart` และรันทุก 6 ชั่วโมง (`apps/api/src/lib/scheduler.ts`) ถ้ากราฟว่างหรือ container ถูก restart บ่อย กราฟจะไม่ถูกเติมเลย | ระบบแนะนำตกไปใช้ "ยอดนิยม" จาก Postgres ทั้งหมด ไม่ได้ลด popularity bias ตามที่ตั้งใจ | ตั้ง `runOnStart: true` ให้ resync (หรือ resync เมื่อพบว่ากราฟว่าง) |
| B3 | กลาง | query แนะนำใช้ราว 1.8 วิ ใกล้ timeout 2 วิ (`NEO4J_READ_TIMEOUT_MS`) บนเครื่องทดสอบ | เครื่องช้าแล้วจะตกไปใช้ fallback แบบเงียบ ๆ | เพิ่ม timeout ในโหมด dev หรือทำ index/ลดขนาด query และ log เมื่อเกิด fallback |
| B4 | ต่ำ | ลบถาวรสำเร็จใน DB แต่ตอบกลับช้าจนได้ 504 แล้วหน้าเว็บไม่โหลดรายการใหม่ | ผู้ใช้เข้าใจผิดว่ายังลบไม่สำเร็จ | หน้า `write/trash` ควรโหลดรายการใหม่หลังได้ error หรือ timeout (น่าจะเกิดจากเครื่องทดสอบ RAM เหลือน้อย ต้องวัดซ้ำบนเครื่องปกติ) |
| B5 | ต่ำ | หน้าแรกทันทีหลัง onboarding ยังไม่มีคำแนะนำ | ผู้ใช้ใหม่เห็นส่วนแนะนำว่างในครั้งแรก | sync `INTERESTED_IN` เข้ากราฟให้เสร็จก่อนพาไปหน้าแรก หรือ fallback ด้วยนิยายตามแท็กที่เลือก |
| — | ข้อจำกัดที่รู้แล้ว | คอมเมนต์ที่ด่าตัวละครเพราะอินถูกตีเป็น neg | ดู `docs/evaluation.md` ส่วน Sentiment | — |

## สภาพแวดล้อม

- Windows 10, RAM 8 GB (ระหว่างทดสอบเหลือว่างราว 0.7 GB), Docker Desktop (WSL2)
- web: `next start` (profile `prod`), api: Express ใน Docker, Postgres 18 บนเครื่อง, Neo4j 5 community ใน Docker
- NLP worker: `my_final_sentiment_model_v2` รันจากเครื่องหนึ่งรอบ (`process_queue`)
